# Design-sync notes — Elber

## Repo-specific setup

- This repo has no separate component-library package — `web/` is the Vite
  app itself. The design-system build is a second, parallel build: `tsup`
  compiles `src/components/index.ts` → `dist-ds/{index.js,index.css,index.d.ts}`
  (script: `npm run build:ds`). The app's own `npm run build` (vite) is
  untouched and unrelated.
- `package.json` `module`/`types` point at `dist-ds/index.js` /
  `dist-ds/index.d.ts` purely so the design-sync converter can find the
  built entry. These fields are otherwise unused (the package is private,
  never published).
- `tsconfig.app.json` has `"ignoreDeprecations": "6.0"` — without it,
  TypeScript 6.0's `baseUrl` deprecation (`TS5101`) fails tsup's `--dts`
  build (tsup's dts worker sets `baseUrl` internally). Needed for
  `npm run build:ds` to succeed, not just for design-sync.
- `dist-ds/` is gitignored (regenerated by `build:ds`).

## Tokens: not a separate package

- `cfg.tokensPkg`/`cfg.tokensGlob` only apply when the DS's design tokens
  ship from a **separate npm package** in `node_modules`. This repo's
  tokens live in the same package (`src/styles/tokens.css`), so that
  mechanism doesn't apply — first build attempt shipped a bundle with
  `var(--*)` references and no definitions.
- Fix: `src/components/index.ts` does
  `import '../styles/tokens.css'` as its first line, so tsup bundles the
  token definitions into `dist-ds/index.css` alongside the component CSS.
  `cfg.cssEntry` is simply `"dist-ds/index.css"` — no `tokensPkg` needed.
- The app's global stylesheet (`src/styles/index.css`) now does
  `@import './tokens.css'` too, so the app and the DS bundle share the
  exact same token source. **If a future edit adds new brand/semantic
  tokens, add them to `src/styles/tokens.css`, not `index.css`** — only
  `tokens.css` is in the DS build's import graph.

## Logo component: no absolute asset paths

- `Logo` originally rendered `<img src="/favicon.svg">`. That path only
  resolves inside the Vite app (served from its own root) — in the
  design-sync preview harness (isolated static HTML, no app server) every
  Logo preview showed a broken-image icon. [RENDER] did not catch this
  because the `<img>` tag itself still "rendered" (non-empty root); only
  eyeballing the screenshots caught it.
- Fixed by inlining the mark as real SVG markup in
  `src/components/LogoMark.tsx`, with gradient `<linearGradient>` ids
  made unique per instance via `useId()` (multiple `Logo`s render on one
  page — e.g. the Logo preview card itself has 3 — so static ids like
  `id="cyan"` would collide).
- **Takeaway for future components**: never reference `/public`-rooted
  asset paths from a component meant to ship in the DS bundle — inline
  the asset (SVG as JSX, or a data-URI) instead.

## Chromium / Playwright for the render check

- No `~/.cache/ms-playwright` on macOS — the cache lives at
  `~/Library/Caches/ms-playwright`. A chromium build was already cached
  there (`chromium-1248`) from earlier use of `chromium-cli`'s fallback
  (raw Playwright via `npx`). Matched it to `playwright@1.64.1` (that
  version's `browsers.json` pins build 1248) and installed that exact
  version into `.ds-sync/` rather than re-downloading a browser.
- The render-check's headless Chromium has **no system fonts** in this
  environment — previews render `--sans`/system-ui as a generic serif
  fallback (visible in the `_screenshots/` PNGs). This is a sandbox
  artifact, not a DS defect: no `[FONT_MISSING]`/`[CSS_RUNTIME]` tag
  fired, the real app (tested separately with a fonts-provisioned
  Chromium) renders the correct sans-serif stack, and claude.ai/design's
  actual hosted renderer is expected to have standard fonts. Don't chase
  this on a future re-sync unless a font tag actually fires.

## Re-sync risks

- `dist-ds/` must be rebuilt (`npm run build:ds`) before any re-sync —
  `package-build.mjs`/`resync.mjs` read the committed `dist-ds/` output,
  not the TS source directly. A re-sync after editing `src/components/*`
  without rebuilding will upload stale output.
- All 5 components are hand-authored previews (`.design-sync/previews/`),
  not floor cards — there is no "unauthored" tier left to backfill, but
  any **new** component added later starts on the floor card until a
  preview is written for it.
- Token names are enumerated in `.design-sync/conventions.md` — if tokens
  are renamed/added in `src/styles/tokens.css`, re-validate the
  conventions file (the base skill's authoring step checks this
  automatically on re-sync and reports drift).
